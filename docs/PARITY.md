# LaserApp Anywhere parity

What advisors do in LaserApp Anywhere today, and where each piece lives in Folium. "Built" means it works end to end in this repo (demo mode, with Power Platform adapters written against the same interfaces). "Needs setup" means the code is in place but depends on an Everence environment, licence or decision. "Later" items are tracked as GitHub issues.

| LaserApp Anywhere | Folium | Status |
|---|---|---|
| **Forms library** — search thousands of forms by name, number, company | Find forms: ranked search across name, form number (`1120`, `EV-1120`), issuer, category and Marketing's keywords (`SWP`, `TOA`, `RMD`). Filters for source, category, favorites and recent. `/` focuses search; `⌘K` searches everything. | Built |
| **Forms always current** — updated daily from form authors | Templates come from Marketing's SharePoint library. Folium always opens the current Live revision; a revision published with a future effective date takes over on that day. Saved packets, favorites and recents resolve to the current revision. A pre-send check blocks stale or retired revisions. Drafts show whether their forms are current ("1 of 3 forms updated", "Out of date"); opening a stale draft, or **Update** on the check, moves it to the current revisions and carries entered values across renamed fields, listing anything dropped first. | Built |
| **Request a form** | "Ask Marketing to add it" sends a form request (`ev_formrequest` row). | Built |
| **Recent forms / favorites** | Recent & favorites screen, plus stars and a "Recently used" filter in Find forms. | Built |
| **Saved forms / packages** | Saved packets: name, describe, reuse; share with your groups or keep private. | Built |
| **Client profile prefill from CRM** | Prefill from the Dynamics 365 contact, the account the form is about, connections (spouse, joint owner, trusted contact) and the advisor's profile. Coverage % shown per form before you add it. | Built |
| **Enter once, use everywhere** | Fields that share a source (or a mapping key) share one value across every form in the packet. "Used on 3 forms — enter it once." | Built |
| **Rep / advisor data** | `rep.*` fields fill from the advisor's details: name, middle initial, title, phones (with extension, mobile and fax), office address, email as printed on forms, rep code, OSJ and RIA numbers, branch. Name, phones, title and office come from the Microsoft directory (`systemuser`) and stay current; a value set in Folium overrides it, shown as "Set in Folium" with a way back. Assistants prefill with the advisor they're working for, directory details included; a firm setting lets advisors work as another advisor in their groups too (Laser App's "User data visibility"). | Built · Needs setup (where rep, OSJ and RIA numbers come from) |
| **Can alter/enter Rep Data** | Firm default plus a per-person override decide who may edit their own rep details. Rep, OSJ and RIA numbers are always Admin-only. Every change to rep data is kept on the profile: who changed which field, from what to what, and when. | Built (UI) · see issue for Dataverse column security |
| **ID documents on forms** (licence, passport, green card, citizenship) | `id.client.*` and `id.spouse.*` sources. When Everence's D365 holds ID columns, name them in `ID_DOCUMENT_COLUMNS` and forms fill from the contact; until then the advisor enters each value once per packet. ID numbers stay out of the session journal, like SSNs. | Built · Needs setup (confirm D365 columns and field security) |
| **Firm data** | `firm.*` fields fill from the Firm profile (legal name, broker-dealer, CRD, address); the firm disclosure is added to envelope emails. | Built |
| **Edit client data** | Contact & accounts: correct the D365 contact and accounts in place, with a confirm step showing old → new. Review edits change one form only and never touch CRM. | Built (demo) · Needs setup (D365 field security) |
| **Missing-data / NIGO checks** | Required fields, formats (SSN, EIN, SSN-or-TIN, dates, ZIP, phone, email, %, $, whole and decimal numbers), per-field limits (ranges, lengths, relative date ranges such as "DOB not in the future"), beneficiary totals, pick-one groups, conditional requirements and stale revisions — checked live on typed and CRM values, each one clickable to the field. Values longer than the PDF box's MaxLen block; overlay text that can't fit warns. | Built |
| **Conditional fields** (lock, conditional required) | Mapping fields carry `requiredWhen` and `lockWhen`. A locked field is read-only, not required and prints blank (read-only in the editable PDF too); unlocking brings back what the advisor typed. Conditions read other fields across the packet or CRM data (`contact.familystatuscode == married`), with `&&`, `||`, parentheses, `contains` and `in (…)`. Admins set them with a builder in the mapping editor and see the result in Test with a contact. | Built |
| **Fill in on the form** | PDF preview with highlights (from CRM / needs input / changed / signer completes / signature tab). Click any field to edit; see where its value came from; put the CRM value back. | Built |
| **Download a fillable PDF** | Download › Fillable PDF keeps every AcroForm field editable with values filled; while checks are open it's stamped "DRAFT — NOT FOR SIGNATURE" (or blocked, by firm setting). Flattened PDF and Print need every blocking check cleared and list all blockers, each linked to its field. | Built |
| **Print / sign in person** | Download to sign in person (flattened, merged) and record it on the request. Blocked, like Send, while checks are open. | Built |
| **User download PDF setting** | Firm setting: downloads allowed, signed envelopes only, or none (e-signature is the only way out). Download, Print and "sign in person" disappear when not allowed. Unlike Laser App's single switch, "signed only" still lets advisors download the completed envelope for OnBase. | Built |
| **End-user location data** | Not collected, by design: nothing in the workflow needs it (DEPLOY.md §6a). | Not applicable |
| **Attach supporting documents** | Attach PDFs (ID, statements, trust pages); they ride along in the envelope. Up to 10 files and 30 MB in all by default (firm setting), with a running count, Remove all, and the envelope's size on the Send screen. | Built |
| **E-signature** | DocuSign through a provider-neutral interface: signer roles from templates, conditional signers (spousal consent if married), routing order or any order (default set by the firm or the advisor), SMS / phone / KBA / email verification, per-signer access codes (never stored), in-session signing on the advisor's device ("Sign now", fresh link each time, audit names the advisor present), CC, subject and note (firm templates with client and advisor tokens; the note can be locked by Compliance), reminders, expiration. | Built (demo) · Needs setup (DocuSign custom connector, IDV workflows, embedded signing on the plan) |
| **Envelope tracking** | Signature requests: Drafted → Sent → Viewed → Signed → In OnBase, with audit trail, Check status, Resend, Correct signer, Void, Download signed PDF + certificate, "Uploaded to OnBase" tick. Open requests show their expiry date (amber within 7 days, with an "Expiring soon" filter); an envelope that lapses shows as Expired, with who had signed and "Start again from these forms". Past-due requests check status on their own. | Built · DocuSign Connect webhook needs setup |
| **Save & resume** | Save draft keeps every value and writes draft PDFs to the contact's SharePoint folder. Drafts & shared lists them with when each expires. Drafts are kept for the firm's retention period after their last save (90 days by default; 0 turns drafts off), then a scheduled flow deletes the row and its PDFs. | Built · Needs setup (clean-up flow, DEPLOY.md §5a) |
| **Session expiry and lost connections** | Every call has a time limit; reads retry and wait for the network; sign-in and connection trouble show one banner. The open packet is journalled to the tab's session storage (SSNs/TINs left out) and offered back after a reload. Leaving with unsaved work asks first. Optionally (Admin › Firm), unsaved work left idle is saved as a draft after a 2-minute countdown in the tab title, instead of Laser App's idle logout. Sends are two-step (DocuSign draft, then release), so an interrupted send resumes without a second envelope. | Built |
| **Form sharing between users** | Share a packet in progress with colleagues; it appears in their "Shared with me" with all values. A firm setting decides who: nobody, people in your groups (default, as Everence's Laser App) or anyone. Saved packets can be shared with groups. | Built (UI) · see issue for Dataverse row security |
| **User groups** | Admins create groups by office, region or team; groups control which forms people see, who they share with, and which advisors an assistant works for. | Built (UI) · see issue for Dataverse row security |
| **User and Assistant roles** | User (advisor), Assistant (works on behalf of the Users in their groups, picks who in the sidebar) and Admin. Requests record who prepared them and for whom. | Built (UI) · see issue for Dataverse row security |
| **Current Users: seats, expiry, suspend, last login** | No seats or expiry dates: access is membership of the Entra ID group the app is shared with, so it ends when someone's Microsoft account does. Users & groups shows each person's status (Active, Dormant after a firm-set number of days, Never signed in, Deactivated, Left Everence), last sign-in (recorded at most once a day), and filters by status, role and group. Deactivating keeps the profile and its requests but takes the person out of groups, acting-for and share lists. The last active Admin can't be demoted or deactivated. | Built |
| **Bulk user changes** | Select people, then change role, add to or remove from a group, deactivate or reactivate, after a confirmation ("Add 12 people to Ohio"). Failures are reported per person. Bulk email is left to Teams/Outlook. | Built |
| **User import / export** | Download the filtered list as CSV for Excel. Import a CSV (`email, role, groups, repCode, branch`) matched to the directory by email and previewed (new / changed / not found / can't import) before anything is saved. | Built |
| **User account settings** | Settings: your details (from your Microsoft profile, with anything changed in Folium marked), sending defaults, email sign-off, insurance licences, appearance. | Built |
| **Admin: forms setup** | Template library (Live / Needs mapping / Draft / Retired), "New from Marketing" queue, mapping editor with revision diff and carry-over, signature tab placement, pre-send check rules, test with a real contact, publish now or on the effective date. Scanned/XFA PDFs get overlay fields. | Built |
| **Works on any device** | Responsive down to phone width; sidebar becomes a drawer; 44 pt touch targets. | Built |
| **Embed in other platforms** | Opens from the Contact record (`?contactId=`) as a Power Apps code app. | Needs setup (spike 1 in the brief) |
| **Other e-signature vendors** | Provider interface ready; only DocuSign implemented. | Later |
| **Automatic OnBase filing** | Manual upload + tick in v1. | Later (phase 2) |

LaserApp's partner integrations (other CRMs, custodians' platforms) are out of scope: Folium is Everence-only by design.
